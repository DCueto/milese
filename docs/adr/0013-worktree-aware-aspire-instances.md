# The AppHost resolves its own port slot and database per git worktree

Mirrors `iplan-nexus-core`'s `Aspire.AppHost/Instances/*` design (see that project's `docs/parallel-development-setup.md` for the full original rationale). `CheckoutLocator` walks up for `.git` to tell the main checkout from a linked worktree (a directory vs. a `gitdir:` file) and reads its name; `InstanceSlotResolver` turns that into a slot — main checkout is 0, a worktree takes its alphabetical position among `.git/worktrees/` entries plus one, falling forward to the next free slot if that one's ports are already held. Every app port shifts by `slot × 100` (`InstancePorts`); the database name follows the *folder* (`milesedb` / `milesedb_<worktree>`), not the slot, so it never moves underneath a running instance. A bare `dotnet run` in any worktree self-configures — no flags, no per-worktree setup, no collision.

Postgres itself is **one shared container** (`milese-postgres`, fixed name, `WithPersistentLifetime()`, `WithEndpointProxySupport(false)` publishing a fixed host port `15432` directly rather than through Aspire's DCP proxy) holding one database per instance — not one container per worktree. This is deliberate: a database container is comparatively heavy to spin up N times, the fixed direct port means a GUI client (TablePlus, DBeaver) stays connected across AppHost restarts instead of losing the proxied port, and `15432` avoids colliding with any locally-installed Postgres on the default `5432`.

**Consequences:** running two checkouts side by side (two worktrees, or a worktree plus the main checkout) just works — verified: main checkout resolved `slot 0, database milesedb, api :5080`, and the container survived `pkill`-ing the AppHost entirely (`docker ps` still showed it `Up`). Milese has no Blazor-WASM-style UI needing a runtime address file rewritten per instance (unlike iplan's `WebApiAddressFile`) since `apps/web`/`apps/mobile` don't exist yet — when they do, each will need its own way to learn the resolved `api` port (an env var for Next.js, a build-time config for Expo), which is out of scope until those are scaffolded.
