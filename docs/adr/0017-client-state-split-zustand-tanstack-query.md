# Both clients split client state (Zustand) from server state (TanStack Query)

`apps/web` and `apps/mobile` both use Zustand for pure client/UI state and TanStack Query for anything fetched from `apps/api`, rather than one library covering both (e.g. Redux Toolkit + RTK Query, or stuffing server data into Zustand directly). Both libraries are platform-agnostic (no DOM dependency), so this is a genuine shared decision, not a compromise for one platform. TanStack Query is adopted once the API-calling code actually needs its caching/background-refetch/invalidation behavior, not committed upfront for every request.

**Why:** the two kinds of state have different lifecycles — server state is a cache of something owned elsewhere and needs revalidation semantics, UI state (open modals, form-wizard step, etc.) doesn't. Splitting them avoids reimplementing cache invalidation by hand inside a general-purpose store, and keeps Zustand itself minimal. On web, auth/account state already lives in `@azure/msal-react`'s own React context and isn't duplicated into Zustand (ADR-0020); on mobile, the equivalent token state lives behind `expo-secure-store` (ADR-0016) for the same reason.
